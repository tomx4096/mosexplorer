# MOS Explorer

Every job in the U.S. military — Army, Marine Corps, Navy, Air Force, Space Force and Coast Guard —
browsable as **service → career field → job**, pulled from each service's own official source and
dressed up as a field terminal. Sibling of [rfcexplorer](https://github.com/tomx4096/rfcexplorer).

## Data sources

| Service | Source | How |
|---|---|---|
| Army | goarmy.com | the JSON endpoint its job pages render from (`/bin/aemservlet/cmtjobs.en.json`) |
| Marine Corps | NAVMC 1200.1M, the MOS Manual (marines.mil) | PDF → `pdftotext -layout` → parsed; primary MOSs only. Recruiting program codes from marines.com |
| Navy | navy.com | career pages from the sitemap, parsed with cheerio |
| Air Force | airforce.com | career pages from the sitemap; AFSC, ASVAB, tech-school fields |
| Space Force | spaceforce.com | the Next.js page data embedded in each career page |
| Coast Guard | gocoastguard.com | its Drupal JSON:API (`cms.gocoastguard.com/jsonapi`) |

Official text is shown as-is under "Official description". The one-line blurbs, "what it's actually
like" paragraphs, fun facts and tags are generated by Claude from that text and are labelled as such.

## Commands

```sh
npm install
npm run data:fetch      # scrape all six services → src/lib/data/ (cached in scripts/.cache)
npm run data:enrich     # Claude pass; needs ANTHROPIC_API_KEY (or reads nothing — see below)
npm run dev             # local dev server
npm run build           # static site → build/
```

`data:fetch` keeps any existing Claude-written fields, so it's safe to re-run when the sources
change. `data:enrich` skips records that already have them; `FORCE=true` regenerates,
`BRANCH=navy LIMIT=20` for a test run. `pdftotext` (poppler) must be on PATH for the Marine Corps.

Requires Node ≥ 22.12 (`.npmrc` relaxes engine checks for Node 23).

## Deploy

Static output in `build/` with a `404.html` fallback; `netlify.toml` is included.
